## Identity and evidence boundary

The [official release page](https://github.com/supabase/storage/releases/tag/v1.73.1) associates v1.73.1 with commit a88e8ee and the September 7, 2026 socket-timeout fix. Local `git rev-parse HEAD` returned the full pinned commit. The source [package.json:139](https://github.com/supabase/storage/blob/a88e8eea60b69ee629f99f17b21cdb6578a2272a/package.json#L139) and [package-lock.json:1-9](https://github.com/supabase/storage/blob/a88e8eea60b69ee629f99f17b21cdb6578a2272a/package-lock.json#L1-L9) both retain version `1.11.2`. This is distinct from release identity. The [release workflow:121-127](https://github.com/supabase/storage/blob/a88e8eea60b69ee629f99f17b21cdb6578a2272a/.github/workflows/release.yml#L121-L127) passes the release version as a build argument, and [Dockerfile:28-41](https://github.com/supabase/storage/blob/a88e8eea60b69ee629f99f17b21cdb6578a2272a/Dockerfile#L28-L41) exports it as `VERSION` and starts `dist/start/server.js`. [config.ts:373](https://github.com/supabase/storage/blob/a88e8eea60b69ee629f99f17b21cdb6578a2272a/src/config.ts#L373) reads `VERSION`.

The local image lock names `public.ecr.aws/supabase/storage-api:v1.73.1` and immutable id `sha256:c24fb33cc2fa38d0f9582a30312907fc56da333fb9ba0646833186197e4982f3`. Reading that lock does not prove that the installed image's compiled files and dependencies came from this source. Image inspection, source labels, compiled behavior and configuration binding need separate evidence. No image was pulled or inspected, no service was started, and no installed binary provenance is claimed here.

## Proposed exact writer inventory obligations

These are acceptance obligations inferred from the mapped source, not implemented recovery behavior.

1. Bind source commit, image digest, compiled provenance, dependency lock, process generation and actual effective configuration. Record backend type/root, queue enable/workers/DB placement, TUS lock/store settings, separator, ETag algorithm, enabled S3/admin/feature routes and replica/Watt worker count.
2. Enumerate all API replicas, every worker process/thread, standalone queue workers, migrations/reconciliation workers and shared-service owners. Bind each to exact environment/database/backend scope and resource identity. Include direct DB sessions, direct filesystem/S3 credentials, scanners and operator tools that bypass gateway admission. Unknown or inaccessible writer owners refuse capture.
3. Close every ingress route that can mutate that scope, including direct Storage addresses, signed upload/TUS, S3 protocol, admin/orphan endpoints, bucket empty, copy/move/delete, database and backend access. Establish an observable admission boundary with process/generation receipts; gateway lease expiry alone is insufficient.
4. Resolve or retain every already-admitted body/file stream, copy, delete, TUS offset write, multipart part/final assembly, fresh-signal metadata transaction, synchronous cleanup and unawaited staging removal. Observe task completion or exact process death and then reconcile durable effects. Do not equate request disconnect, HTTP response, DB lease disposal or file backend close with completion.
5. Inventory relevant pg-boss pending, scheduled, active, retry and dead-letter jobs in their actual queue DB and schema, including payload tenant/object/version and replacement follow-on jobs. Either prove they cannot execute during capture or preserve them with a verified restart policy. Pausing polling in one process does not close other workers or inline fallback.
6. Inventory TUS configstore records and bytes, multipart upload/part rows and staging bytes, `.info` files, part xattrs, S3 multipart state and S3 lock objects where applicable. Decide explicitly how unfinished resumable uploads are captured/recovered; prove completed versus incomplete state with original protocol evidence and exact bytes.
7. After all writers are closed, reconcile reachable Storage rows with version-resolved backend paths and native metadata. Preserve xattrs and exact available nanosecond mtime. Verify native stat length against row size and original API reads. Compute independent SHA256 after closure, then compare after restore. Same-version changes, equal length and mtime-based ETags require exact byte proof. Missing or inconsistent reachable bytes fail acceptance; do not edit row metadata or regenerate ETags to satisfy the check.
8. Keep environment-only and shared captures separate in scope but close every writer that can reach each scope. Publish denied/unreachable inventory entries and unrun feature cases. Prove crash/forced-stop reconciliation and reopened writes with actual original services before claiming recovery readiness.
