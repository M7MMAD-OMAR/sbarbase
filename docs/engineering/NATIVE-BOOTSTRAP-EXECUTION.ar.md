# فحص تشغيل PostgreSQL الأصلي

فحص التشغيل المحلي يتطلب نتيجة تنفيذ أصلية ناجحة وحديثة والتحقق من تنظيف
الموارد الخاصة به. نجاح اختبارات المصدر وحفظ الإعدادات لا
يثبت تشغيل قاعدة البيانات أو عمل SDK أو الاستعادة أو الجاهزية للإنتاج.

## ما تغير

صورة فحص الهوية تعمل بحساب root مع إسقاط جميع الصلاحيات الإضافية. بعض ملفات
الأدلة المنسوخة داخلها كانت قابلة للقراءة من مالكها فقط، ومالكها حساب آخر.
لذلك فشل حساب root في قراءتها وحساب بصمة المصدر.

تم تعديل `deploy/verify/Dockerfile.identity` بحيث يصبح حساب root مالك نسخة
المصدر العامة داخل صورة الفحص. محتوى الملفات وأوضاعها لم تتغير. صلاحيات ملفات
المضيف وصور خدمات الإنتاج والفحص غير الجذري للمصدر تبقى كما كانت.

## نتيجة المحاولات بتاريخ 2026-10-10

المحاولة الأولى توقفت عند قراءة ملف دليل، قبل بدء التهيئة. بعد إصلاح الملكية
نجحت قراءة المصدر وحفظ الإعدادات. المحاولة التالية توقفت لأن Docker استنفد
نطاقات الشبكات التلقائية. قاعدة البيانات لم تبدأ، ونتيجة الخروج 1 محفوظة
كفشل، وليست نجاحاً جزئياً للتشغيل.

مراجعان مستقلان تحققا من ملفات نتائج المحاولة الثانية ومن غياب الموارد
المؤقتة الخاصة بها بعد التنظيف. لم تُحذف شبكات المشاريع الأخرى.

## الخطوة المتبقية

تم تنفيذ اختيار تلقائي لنطاق `/28` من مجموعة الاختبار `10.240.0.0/16` بعد
فحص جداول مسارات IPv4 وشبكات Docker الحالية. الفحص يرفض التداخل والبيانات
الملتبسة والتغير أثناء الرصد، ويحفظ الملاحظات والبصمات. يقتصر على اختبارات
bootstrap وconfigured-effects ولا يغير إعدادات Docker العامة.

الحدود: 15 ثانية للرصد، و5 ثوان لكل أمر، و1 MiB للمخرج و16 KiB لمخرج الخطأ،
و256 شبكة و4096 مساراً و4096 نطاقاً مرشحاً. يجب ألا يزيد عمر النتيجة عن 60
ثانية عند إنشاء الشبكة. يجري التحقق من ملكية الشبكة ونطاقها قبل بدء قاعدة
البيانات. فحص المسارات لا يقفل تغييرات المضيف الأخرى، والنتيجة سجل محلي وليست
تصريحاً موثق الهوية. Docker يرفض التداخل المتزامن بدلاً من حذف شبكة أخرى.

اختبارات المصدر لا تثبت التشغيل. يجب إعادة التنفيذ الأصلي ومراجعته بصورة
مستقلة. الخطة الكاملة وحقول قبول القدرات الـ105 ومرحلة الإنتاج تظل مفتوحة.

التفاصيل والبصمات وحدود التنفيذ في [النسخة الإنجليزية](NATIVE-BOOTSTRAP-EXECUTION.md).
