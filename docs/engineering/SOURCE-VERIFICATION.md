# Public source verification

Run `sh deploy/verify/run.sh` from a checkout with Docker Linux container support. A destination argument selects a fresh receipt directory. The runner builds the public verifier image, executes all seven source stages and copies their original logs, exit statuses, source identity and environment metadata. It removes only the exact container and tagged image created by that invocation.

The verifier has no network, host mounts or Docker socket. It drops capabilities and uses no-new-privileges, a 1 GiB memory ceiling without additional swap, one CPU and a 512 process ceiling. Temporary fixtures use a private container tmpfs at `/tmp`, limited to 512 MiB with nosuid and nodev. The exec option is explicit because the test suite executes copied shell entrypoints and fake command fixtures from its temporary directories. Docker's default noexec tmpfs refused those fixtures in a preserved failed intermediate attempt. Memory used by tmpfs remains subject to the container memory ceiling.

The temporary filesystem is intentional. An actual 2026-10-10 run on the host Docker overlay filesystem observed directory link count 1 and an empty descriptor-based directory listing after a file was created through the pathname. Transfer journal fixtures correctly refused the directory policy, and recovery cleanup correctly refused a mismatched member inventory. The public verifier now supplies conventional temporary directory semantics for those tests. It does not weaken private ownership, link count, path anchoring, file inventory or fail-closed cleanup in the product. This is a source test environment contract, not proof that an arbitrary deployment data filesystem is supported.

A stale catalog-schema binding after the current management changes was another reproduced cause. That one binding is refreshed to the current catalog source; capability acceptance and production claims remain unproven. Keep the original report and logs instead of editing them into a pass.

The source stages are planning integrity, all Python unit tests, all Bun tests, both TypeScript checks, console build and Python compilation. Empty or skipped Python and Bun tests refuse acceptance. A successful source run accepts only its frozen source snapshot and container environment. Native services, fresh host installation, transfer, recovery, provider DNS/TLS/email, resource measurements, maintenance, soak and public release require separate current evidence from the engineering programme.

Local checkpoint artifacts and receipts are stored outside the checkout. Their consistency hashes are useful audit bindings, not authenticated independent certification. The run is a prerequisite to continuing the full programme, not a replacement for its remaining requirements.
