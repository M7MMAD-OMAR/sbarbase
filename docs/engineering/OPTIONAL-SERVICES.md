# Optional services: the Services page, hints, and On demand

Plan: [2026-10-30-optional-services](plans/2026-10-30-optional-services.md). Guide: [Services](../guides/services.md). Each phase adds a section here.

Optional services are the ones an environment can run or not: Realtime (320 MiB ceiling), Edge Functions (384 MiB), direct database access, scheduled jobs and Studio. Auth and REST are not optional and are not on this page.

## S1: the Services page (read model)

`GET /management/v1/environments/{id}/services` (`src/control/services.ts`, `catalog.services`) answers every member of the organization, viewers included; the switches stay on the existing routes (`PUT .../realtime|functions|scheduled-jobs`), owners and admins only, with their audit events and 409s unchanged. The answer carries state, the reason of a failure, memory now and its ceiling, last use, what turning it on adds, open Realtime sockets or Functions calls in flight, and the host's free memory. It carries no key, address, variable or log.

- **Memory.** The console process has no Docker socket. The supervisor samples `docker stats` for the installation's containers once a minute in a thread (`lab/service_stats.py`, called from `lab/dev.py`) and writes `.lab/upstream/service-stats.json` (0600, one rename). `readStats` refuses a file over 256 KiB, a version it does not know, a container name outside the pattern and any non-integer figure. A sample older than 3 minutes is `stale` and its numbers are not shown as current. The file also holds the cost of one more Realtime or Edge Functions container, taken from `resource_policy.TIERS`, so the page never duplicates a constant.
- **Last use.** `src/gateway/activity.ts` (`ServiceActivity`) is told by the gateway: a Functions call after its API key was verified (`src/gateway/managed.ts`; a request that failed authentication never counts), and a Realtime socket accepted by the front listener (`UpgradeDecision.onOpen`, called once the socket reaches Realtime, released when it closes). Times are kept in memory and written to the catalog table `service_activity` at most once a minute, a later time winning. In flight Functions calls are the gate's own count (`ConcurrencyGate.inFlight`), so a call counts until its answer has ended. Direct database access and scheduled jobs record no last use; the page says "Not recorded". Studio uses its existing `studio_activity`.
- **Quiet time** (`ServiceActivity.quietFor`, used from S3): never quiet while a socket is open or a call is in flight, within the window of the last use, or before this process has itself been up for the window.
- **Not a change of behaviour.** Nothing here starts or stops anything; Realtime, Functions, database access and scheduled jobs are off for a new environment exactly as before.

## S2: hints, never actions

`unusedHint` (`src/control/service-hints.ts`): a service that is plainly on (not starting, stopping, failed), with nothing open, not in On demand mode, and whose clock (the later of last use and the time it was turned on, `updated_at` of its settings row) is at least `unusedDays` old. `ServiceView.unused` carries `{days, neverUsed}` and the Services page shows it with a button that goes through the same confirm as the switch. `checkUnusedServices` runs from `lab/upstream-app.ts` two minutes after a start and then hourly: one `service.unused` operator notice per service (kind and reason added to `catalog.ts` and `lab/notify.py`, severity info), repeated at most every 14 days by `service_hints` (the outbox window of an info event is an hour, so the table is what spaces the repeats). It never writes a service row.

The days are `installation_services.unused_days`, default 7, floor 1, ceiling 365; `GET`/`PUT /management/v1/installation/services` (installation operators only, an out of range value is refused, each change an audit event `services.settings_changed`). The catalog moved to schema version 7 for the two tables; the previous release refuses it, as for version 5 and 6, so the way back is the pre-upgrade snapshot.

## S3: On demand mode

**Measured first** (`lab/on-demand-check.py`, evidence in `docs/evidence/optional-services-2026-10-30/`): wake to first answer is 1.9 to 2.5 s for Edge Functions and 12.3 to 14.8 s for Realtime (about 11 s is the upstream Realtime's start to its health check). The gate is the 10 s supabase-js gives a channel to join, so Edge Functions are On demand by default for new environments and Realtime is not: `ON_DEMAND_BY_DEFAULT` in `src/control/on-demand-policy.ts`, and Realtime On demand needs the installation setting `realtime_on_demand`. The check builds a disposable installation (its own network, one PostgreSQL, placeholder Auth and REST; the retained lab, `.lab`, `.secrets` and volumes are never touched) and drives the real `Runtime.realtime_turn` and `functions_turn`. It also proves the replication slot: none of the environment's slots after a sleep, and one again once a client joins after the wake (5 of 5 each time).

**Model.** The saved choice is `service_modes(runtime, service, mode, idle_minutes)` (catalog schema version 8); whether the container runs is still the `realtime_settings` / `functions_settings` row. Sleeping is `mode='on_demand'` with state `off`; waking is `pending` with desired `on`. A runtime with no `service_modes` row has the mode its settings row implies, so every existing environment keeps what it has. `PUT .../realtime|functions` still takes `{"enabled"}` (On or Off, replacing any On demand choice) and now `{"mode","idle_minutes"}`. New environments get `installation_services.default_mode` at provisioning success (`applyDefaultModes`), for the services where On demand is available, and never start anything.

**Wake** (`OnDemand.ensure`, `src/control/on-demand.ts`; called from `src/gateway/managed.ts` and `src/gateway/realtime.ts`): only after `gatewayKeyAccess` verified the key, or, for Edge Functions without a key, for a function with `verify_jwt` off (`isPublicFunction`, kept two seconds). It writes the pending row as `system:wake` (an audit event `*.wake_requested` with the reason), the supervisor applies it with `--wake` for Realtime (the same admission as a manual start; the superuser migration window is skipped when the pinned image did not change, remembered in `endpoints.json` as `asleep.realtime.migrated`), and the request is held up to 20 s, then `503` with `retry-after`. Wakes of one service share one wake, run one at a time on the installation (`tail`), are limited to 6 an hour per service and environment (`wakesInWindow`, indexed audit events, kill switch wakes not counted) then `429`, and at most 64 requests wait per environment. A wake touches the activity, so the sweeper cannot put it to sleep before its request is served. A sleeper stop that the supervisor has not applied yet is called off by the next request (`cancelSleep`).

**Sleep** (`OnDemand.sweep`, every 10 s, decisions once a minute): a quiet service (`ServiceActivity.quietFor`: nothing open, nothing in flight, no use for the whole quiet period, console process up that long) gets a `system:idle` request; the supervisor applies it with `--sleep`, which removes the container, closes the login, ends the sessions and drops Realtime's slots (`realtime_drop_slots`: only `supabase_realtime%` slots, active walsenders ended first, looked at again until none is left, an error if one remains). Restart, update (`lab/rolling.py` replaces Auth and REST only), backup and restore start only what `endpoints.json` names, and a sleeping service has no entry (`lab/test_realtime.py` pins this). A manual Edge Functions off drains: new calls get `503` for the drain, the running ones up to 10 s (`ServiceActivity.beginDrain`).

**Kill switch** (`installation_services.kill_switch`): the sweeper wakes sleeping On demand services one at a time (`system:kill-switch`, a failed start is tried again after ten minutes) and sleeps nothing; saved modes are untouched.

**Audit.** Every request is an event with its actor and reason (`user`, `wake`, `idle`, `kill_switch`, `default`), every supervisor outcome `*.applied` or `*.apply_failed` (`capacity` for a refusal for room) with its seconds, every mode change `*.mode_changed`, a called off stop `*.sleep_cancelled`.
