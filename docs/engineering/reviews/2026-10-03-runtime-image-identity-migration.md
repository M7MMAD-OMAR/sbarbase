# Runtime image identity migration inventory

Reviewed 2026-10-03. This foundation accepts repository-qualified immutable lock references and exact daemon repository association for installer admission and the read-only pinned-image checker. It does not establish complete runtime/store portability.

## Identity contract

The lock `id` remains a logical full SHA-256 content digest. Its declared tag identifies a repository but is never pulled or used as runtime authority. Every lock digest must identify that same repository and digest after explicit Docker Hub alias normalization. The resolved native daemon `Id` can differ from the logical pin, for example a configuration ID in the classic image store. Runtime comparisons must use the daemon ID obtained from inspection of the exact immutable repository reference. Bare-ID, tag, substring and unrelated repository proof are refused.

Installer inventory and pull admission use exact references. Existing malformed daemon proof blocks before a pull. Missing exact references can be pulled only when native stdout is an empty JSON list and a single known English daemon error names that exact immutable reference. Permission, connection, missing diagnostic, unexpected locale/Engine format and ambiguous errors block before any accumulated pulls. Native diagnostics remain visible. A successful pull still requires exact native proof. The standalone checker never pulls, and its mail diagnostic caller uses the same proof. Service image lock values and upgrade intents are unchanged.
