## What changed

Studio builds from 2026-09-07 to 2026-10-12, about 380 commits to `apps/studio` (step A6 of the [upstream currency plan](../engineering/plans/2026-10-14-upstream-currency.md)). Most of them touch platform-only pages (billing, organizations, OAuth apps, pipelines, log drains) that self-hosted Studio does not show. Relevant here:

- The Database Connections page left feature preview ([#50107](https://github.com/supabase/supabase/pull/50107)): it lists the sessions of the current database and can cancel one by its process id.
- SQL identifiers are escaped in the table definition and in row export ([#51258](https://github.com/supabase/supabase/pull/51258), [#51256](https://github.com/supabase/supabase/pull/51256)), and the SQL export no longer swaps numeric values ([#51382](https://github.com/supabase/supabase/pull/51382)).
- Column defaults set to `NULL` produce valid SQL ([#50097](https://github.com/supabase/supabase/pull/50097)); `sharp` stays out of the self-hosted standalone build ([#50658](https://github.com/supabase/supabase/pull/50658)).
- Storage object versioning pages ([#49205](https://github.com/supabase/supabase/pull/49205), [#49208](https://github.com/supabase/supabase/pull/49208)), which need Storage v1.81.0 or later (A5 pins v1.83.3).

## Affected surfaces

Studio only: one container per environment while a Studio session runs (`lab/studio.py`), reached through the console's Studio proxy. It connects as `<e>_studio`, which is NOSUPERUSER and NOINHERIT and holds no `pg_signal_backend`, so the Connections page can see the query text and cancel only the sessions of that same login; other services' sessions show without their queries and cannot be cancelled. postgres-meta is a separate pin (its own step). No schema, HBA, Auth, REST or Storage change.

## Breaking changes and migrations

None for self-hosted Studio. It runs no migrations.
