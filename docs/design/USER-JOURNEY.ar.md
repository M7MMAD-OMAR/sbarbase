# بحث تجربة المستخدم وتحليل الرحلة الكاملة

تحديث 2026-10-10. يشمل التحليل واجهة الإدارة الحالية والانتقال إلى Supabase Studio الأصلي، مع تنفيذ MFA الاختياري وproduction من الخطة السابقة. الأدلة قراءة للكود وتجارب تفاعل محلية، وليست مقابلات مستخدمين أو قبولاً على خادم الإنتاج.

الهدف: اسم المشروع ثم Create، وبعده يتولى النظام التجهيز والوصول إلى اللوحة. تبقى الجداول وSQL ومستخدمو Auth وStorage في واجهة Supabase الأصلية. تبقى إدارة التثبيت وإعداد خدماته في النظام الحالي.

## الفرق عن السابق

كان إنشاء المشروع ينتهي بصفحة التجهيز ثم ضغطة لفتح اللوحة، وكان مسار Studio قد يمر بغلاف ومحرر مضمّن. الآن يكمل Create رحلة التجهيز والتشغيل والفتح في تبويب مستقل، وتظهر واجهة Supabase الأصلية كوجهة مباشرة. زيارة مشروع موجود تبقى تحت تحكم المستخدم.

يبقى عنوان مساحة العمل القديم محدداً اختيارياً للبيئة دون تضمين Studio. يحتفظ التبديل بلقطة البيانات ضمن الصلاحيات وتذكرة خاصة بالهدف.

## حالات الفشل والتحقق

يفصل النظام فشل الإنشاء والتجهيز وتشغيل Studio وجلب حالته. إعادة جلب الحالة أو فتح لوحة يجري تشغيلها لا تنشئ مشروعاً جديداً ولا تعيد طلب التشغيل المعلق. إلغاء الانتقال أثناء الطلب يمنع التنقل، ولا يلغي تجهيزاً اكتمل. لا تتكرر المحاولة التلقائية بلا حدود بعد الفشل.

يختبر `lab/project-workflow-browser.ts` البناء الفعلي للواجهة والتطبيق والوكيل، مع خدمات Auth وStudio نموذجية معزولة. يشمل الإنشاء بلوحة المفاتيح، والفتح التلقائي، وحفظ النظام، والإلغاء، والتبويب المغلق أو المحظور، ورفض الإنشاء، وإعادة المحاولة، والهاتف، وكشف الإعدادات المتقدمة، وتفعيل MFA وإبطال الجلسات. تتحقق `tests/studio-navigation.test.ts` من الدخول الأصلي وحفظ المحتوى والترويسات والتبديل الاختياري الآمن. تبقى اختبارات الصلاحيات وCLI ودورة الموارد وسجل النقل مطلوبة.

توجد أعداد الفحوص وتقارير المراجعة في تصدير التحقق. لا تثبت التجارب المحلية نشراً فعلياً أو تشغيل حاويات أصلية أو تغيير DNS أو سياسة تثبيت حي.
