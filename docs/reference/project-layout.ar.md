# هيكل المستودع

يبني صباربيز طبقة إدارة وتشغيل فوق خدمات Supabase الأصلية. تساعد هذه الخريطة في العثور على الكود والأدلة والإجراءات؛ ولا تعني أن المشروع اجتاز قبول الإنتاج.

| المجلد | ما تجده فيه |
|---|---|
| `src/` | طبقة التحكم وفهرس البيئات والبوابة وواجهة الإدارة البرمجية، مكتوبة بـ TypeScript |
| `ui/` | لوحة المشغّل؛ أما إدارة بيئة Supabase فتستخدم Studio الأصلي |
| `lab/` | أدوات التشغيل والإدارة المكتوبة بـ Python، وبيئات الاختبار والفحوص الحية؛ اقرأ ملف README فيه قبل تشغيل حاويات |
| `tests/` | اختبارات TypeScript |
| `deploy/` | إعدادات حاويات Docker، وسكربتات الخادم، وأدوات التحقق المعزولة |
| `fragments/` | ملاحظات تطوير وتفاصيل تنفيذ محددة |
| `docs/explain/` | شرح التصميم وحدوده |
| `docs/guides/` | إجراءات المشغّل |
| `docs/reference/` | الحالة والإعدادات ومرجع API |
| `docs/decisions/` | القرارات وبدائلها وشروط إعادة النظر فيها |
| `docs/engineering/` | الملاحظات المؤرخة والخطط والمراجعات وتعليمات متابعة العمل وسجل الأدلة |
| `docs/evidence/` | نتائج منشورة لتجارب حية سابقة، يحتفظ كل منها بنطاقه وتاريخه |
| `website/` | الموقع العام، وله سير عمل مستقل للبناء |
| `film/` | مصادر إنتاج الفيديو الشارح |
| `graft/` | خريطة سياق الكود وروابط الملفات والرموز |

نسخة التطوير المعلنة في الحزمة 0.2.0. يحتفظ [سجل التغييرات](../../CHANGELOG.ar.md) بتاريخ إصدار المصدر 0.1.0. وتجمع [الحالة](status.ar.md) الميزات وحدودها، بينما توضح [جاهزية النشر](deployment-readiness.ar.md) ما جُرّب وما يحتاج إلى إثبات.

## ما يرجع إليه العمل الحالي

تحدد [أهداف المشروع](../../PROJECT_GOAL.md) و[خطة المنتج](../engineering/plans/2026-10-03-product-and-portability-plan.md) و[طريقة التنفيذ والتحقق](../engineering/plans/2026-10-03-gauntlet-execution-method.md) اتجاه التطوير الحالي. ويفصل [عقد مكان التشغيل الأصلي](../engineering/plans/2026-10-03-native-placement-identity.md) البنية المستقلة التجريبية عن البنية المشتركة العاملة.

يربط [سجل الأدلة](../engineering/gauntlet-ledger.json) كل نتيجة بنسخة مصدرها ونطاقها، ويحتفظ بالتجارب الناجحة والفاشلة. بعض مساراته تشير إلى ملفات محلية لا توزّع مع المستودع؛ فلا تُعد أدلة عامة منشورة. وتبقى خطط سبتمبر ونقاط التحقق المؤرخة سجلات سابقة.

## التحقق من المصدر

من جذر المستودع، يعمل التحقق المعزول عبر Docker بهذا الأمر:

```sh
sh deploy/verify/run.sh
```

ينشئ الأمر حاوية تحقق مؤقتة بحدود موارد محددة، ويشغّل الفحوص دون اتصال بالشبكة، ويحفظ الأدلة في `.lab/` المستبعد من Git. تفاصيل النطاق في [دليل التحقق](../../deploy/verify/README.md). يشغّل CI أيضًا تجارب تثبيت Docker وقبول الخادم الفارغ؛ ولا تثبت هذه الفحوص الاستعادة الكاملة أو دعم كل الخوادم أو الجاهزية للإنتاج.

يحتوي `.lab/` و`.secrets/` على حالة محلية خاصة لا تدخل في نشر المصدر. كذلك تُولّد مجلدات الاعتماديات ومخرجات البناء أثناء العمل، ولا تحل محل ملفات إصدار يمكن إعادة بنائها والتحقق منها.
