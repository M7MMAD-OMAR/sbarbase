# الحالة الحاليّة

يشمل الرصد حتى 2026-11-14. يميّز هذا المرجع بين إصدار المصدر المنشور، والنسخة المثبّتة على الخادم، ونطاق اختبارات التشغيل.

## الإصدارات والعناوين

| العنصر | الحالة المرصودة |
|---|---|
| إصدار المصدر | الإصدار 0.13.1؛ راجع [أحدث إصدار على GitHub](https://github.com/M7MMAD-OMAR/sbarbase/releases/latest) للتحقق من النشر وملفّات التنزيل |
| تثبيت المالك | الإصدار الموقّع v0.13.1 (`992be52`)، ثُبّت عبر قناة الإصدارات المعتادة وأكّدت آليّة التحديث تشغيله في 2026-11-14 ([الدليل](../evidence/server-pgmq-bridge-2026-11-14.json)) |
| موقع التوثيق | [base.sbarah.com](https://base.sbarah.com/)، بالعربيّة تحت `/docs/` وبالإنجليزية تحت `/en/docs/` |
| لوحة المالك | `https://sbarbase.sbarah.com`؛ ولكلّ تثبيت آخر عنوانه المضبوط |
| نسخة التطوير | قد تحتوي تغييرات غير منشورة. يُعرف محتواها من إيداع Git وملف الإصدار، ولا يدلّ رقمها وحده على النسخة المثبّتة |

يحذف الإصدار 0.13.1 تصريح ترحيل PGMQ الموروث، فيصنّف المحدّث المعتاد في 0.11.2 وما بعده الانتقال تحديثًا عاديًّا. أصبح إصلاح PGMQ مؤجّلًا: لا يعمل إلا عبر `lab/backup.py repair-pgmq` بعد نسخة احتياطيّة متحقّق منها تحفظ الطوابير القديمة، أو على أرشيف مستعاد اجتاز حارس الأرشيف القديم. راجع [الترقيات](../guides/upgrades.ar.md). ولا تتغيّر صور الخدمات المثبّتة. تبقى ملاحظات لوحة التحكّم الخاصّة وSMTP في 13 نوفمبر أدناه سجلًّا تاريخيًّا.

## ما تغيّر في لوحة الإدارة

- تميّز ألوان الأسطح بين مستويات الارتفاع، مع إبقاء مؤشر التركيز واضحًا عند استخدام لوحة المفاتيح.
- تبقى محدّدات مساحة العمل وأزرار تذييل القائمة ظاهرة أثناء تمرير روابط التنقّل. ويمكن اختيار المشروع والبيئة مباشرة.
- تُحمّل مساحة الاتصال عند فتحها، وتعرض خيارًا للاستعادة عند فشل التحميل. ويطلب النظام تأكيدًا قبل ترك مسوّدة دالة Edge غير منشورة.
- يبيّن عنوان التبويب اسم المشروع والبيئة. ويضيف Studio اسم عرض آمنًا في معامل `workspace` بالرابط، مع بقاء مضيف البيئة والتفويض الموقّع أساسًا للتوجيه والوصول.
- تتّبع قوائم الاختيار ألوان الواجهة في المتصفّحات التي تدعم تخصيصها، وتبقى القوائم الأصليّة متاحة في غيرها.

تجد التفاصيل في [تصميم اللوحة](console-design.ar.md) و[دليل Studio](../guides/studio.ar.md).

## رصد 14 نوفمبر

نُشر المصدر `0044cb6` على خادم المالك، وأكّدت آليّة التحديث تشغيله. شمل الفحص الحذف عبر Management API وأرشفة مشروع `i2s`، واستعادة عامل المالك بأمر root المحليّ والتحقق منه عبر وكيل الإدارة. تخصّ النتائج هذا المصدر وحده؛ ويلزم التحقق من هوية مصدر 0.13.0 النهائيّ ونتيجة تثبيته عند الإصدار.

يشمل الإصدار 0.13.0 20 صلاحية للرموز تغطّي 39 عملية عبر API وMCP، والقراءة افتراضيًّا، والمنح الصريح للعمليات الخطرة، ونقل الرموز القديمة إلى القراءة. ويشمل أرشفة المشاريع مع الاحتفاظ ببيئاتها المحذوفة واستعادتها للمالك، واستعادة المالك الوحيد بأمر محليّ بصلاحيّة root مع التحقق من العامل عبر وكيل الإدارة ومسارًا منفصلًا يتطلّب مالكين، وإصلاح مسار Auth لإجراءات البيئة. ويصلح SMTP وتحميل القوالب والتخزين المؤقّت للملفات الخاصّة في Studio، والتحقق من الإصدار مع اختلاف ترميز gzip. راجع [ملاحظات الإصدار](../../CHANGELOG.ar.md).

## نتائج سابقة في 13 نوفمبر

في تحديث اللوحة الأوّل عند `53b43da`، نجحت اختبارات الحزمة باستخدام Bun وعددها 1610، واختبارات الترقية باستخدام Python وعددها 185. واجتازت النسخة كذلك فحوص الأنواع، ونجح بناء الواجهة والموقع، ونجحت فحوص المتصفّح المعزولة للوحة وعددها 46. وشمل فحص منفصل صورة Studio المثبّتة على خادم المالك عبر عنوانها العامّ: اسم المشروع في التبويب، واسم العرض في الرابط، وتحميل ملفات الهويّة بعد التحقّق من الصلاحيّة، وبقاء هذه العناصر بعد إعادة التحميل. وأعادت طلبات صحّة Auth وطلبات REST الحالة HTTP 200 في البيئات الأربع باستخدام مفاتيحها العامّة الموجودة.

أُنشئت نسخ احتياطيّة جديدة للبيئات الأربع والبيانات الوصفيّة المشتركة لـ Storage وحسابات الإدارة، وفُحصت بصمات الملفات وإمكان قراءة الأرشيفات. ولم تُجرَ استعادة كاملة منها في هذه الجولة. بقيت حاوية قاعدة البيانات وصور الخدمات العاملة كما كانت، وأُعيد إنشاء بعض حاويات الخدمات بالصور نفسها أثناء إعادة التشغيل. يسجّل [تقرير التحديث](../evidence/server-console-2026-11-13.json) هذا النطاق المحدّد.

لا تثبت هذه النتائج نجاح تثبيت جديد أو ترحيل صورة PostgreSQL أو استعادة خادم كامل أو سعة حمل محدّدة أو دعم جميع ميزات Supabase Cloud.

اجتاز مرشّح إصلاح SMTP اللاحق 1657 اختبارًا باستخدام Bun وفحص الأنواع و18 فحصًا معزولًا لـ Studio الأصليّ عبر المتصفّح، منها محاكاة CDN بملفات قديمة. وعرض الخادم العامّ النموذج الأصليّ بقيم إعدادات البيئة الخاصّة التي طُبّقت. أعاد طلب إرسال بريد واحد عبر Auth الحالة HTTP 200، ثمّ حُذف حساب الاختبار المؤقّت. قبول المزوّد للطلب لا يثبت وصول الرسالة إلى صندوق الوارد. راجع [تقرير SMTP](../evidence/server-smtp-2026-11-13.json).

## العمل المتبقّي

- تبقى الإزالة النهائيّة مرفوضة. وما زال التأهيل الكامل لـ Storage وزمن الاستجابة العامّ لـ Studio عملين مفتوحين؛ لا تثبت الإصلاحات المحدّدة أداءً عامًّا.
- تقتصر إصلاحات توافق SMTP والقوالب على صورة Studio المثبّتة. ولا يشملها الإصدار العامّ v0.12.2.
- فُحص جسر PGMQ في 0.13.1 على قاعدة بيانات مؤقّتة (`lab/pgmq-check.py`) وباختبارات الوحدات. لم يُشغَّل `repair-pgmq` ولا استعادة كاملة عبر `backup.py restore` تعيد تشغيل الملحق على تثبيت حقيقيّ فيه طوابير، ولا تغطّي الطوابير غير المسجّلة في السجلّ (unlogged) إلا اختبارات الوحدات. الطوابير المقسّمة غير مدعومة. ولا تستطيع الإصدارات السابقة لـ 0.13.1 جلب مجموعة خارجيّة أو استعادة نسخة تحمل `pgmq.sql`.
- تحتاج ترقية صور الخدمات، ومنها PostgreSQL 17.11، إلى فحوص مستقلّة للتوافق والترحيل والاستعادة. لم يعتمد تحديث اللوحة الخاصّ أيّ مجموعة صور مرشحة.
- يبقى `pg_stat_statements` محظورًا لحماية عزل البيئات. ولا تضيف صفحة Studio ذاتيّة الاستضافة الفوترة المستضافة أو فروع Git أو غيرها من الميزات غير المدعومة.

يوضّح [مرجع جاهزيّة النشر](deployment-readiness.ar.md) ما بقي من شروط القبول، ويبيّن [دليل الوكلاء](../guides/agents.ar.md) اختلاف توفّر واجهات API وMCP بين الإصدارات.
