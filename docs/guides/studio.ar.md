# Supabase Studio لكل بيئة

تستطيع كل بيئة فتح Supabase Studio الأصلي: محرر الجداول، ومحرر SQL، والمستخدمين، وحاويات Storage، وكلها على تلك البيئة وحدها. يعمل Studio فقط حين يحتاجه أحد، ومن خلف تسجيل الدخول إلى الواجهة، فلا يكلّف شيئًا وهو مغلق.

## افتحه

1. سجّل الدخول وأنشئ مشروعاً. ينشئ النظام **production** ويفتح تبويب انتظار نتيجة ضغطك على Create.
2. يجري تجهيز البيئة ثم تشغيل Studio وفتحه تلقائياً في ذلك التبويب. تبقى صفحة النظام مفتوحة. يلغي **Stay in console** أو إغلاق تبويب الانتظار فتح اللوحة تلقائياً.
3. للمشروع الموجود اضغط **Open Supabase dashboard** مرة واحدة. يشغّل النظام Studio عند الحاجة ويفتح صفحته الأصلية كاملة على `<id>.studio.localhost` ومنفذ الواجهة نفسه، باستخدام جلستك الحالية. لا يضاف شريط خاص أو iframe داخل Studio.
4. تفتح **Connection details** إعدادات البيئة. يعرض **Database connection** إيقاف اللوحة وإعدادات الاتصال المباشر. يضبط **Sign-in settings** خدمة Auth المستضافة ذاتياً، بينما تبقى إدارة المستخدمين في Studio الأصلي.

إذا حظر المتصفح تبويب الانتظار، يجهز النظام اللوحة ويتيح زر الفتح المعتاد. عند فشل التشغيل يغلق التبويب المؤقت وتبقى رسالة قابلة لإعادة المحاولة في النظام. يعالج **Retry dashboard status** فشل جلب الحالة. عند فشل تجهيز البيئة استخدم **Retry** في صفها. لا تنشئ إعادة المحاولة مشروعاً آخر. اسم production لا يعني أن التثبيت اجتاز قبول الإنتاج.

وحدهم مالكو العميل ومديروه يستطيعون تشغيل Studio أو فتحه أو إيقافه. المشاهدون لا يرونه.

على خادم، ادخل إلى الواجهة عبر نفق SSH (`ssh -L 8790:127.0.0.1:8790 your-server`) كما يشرح [دليل Docker](docker.ar.md). المتصفحات ترسل كل اسم `*.localhost` إلى جهازك نفسه، فيمر تبويب Studio عبر النفق نفسه دون أي إعداد إضافي.

## ماذا يستطيع

| الصفحة | تعمل على |
|---|---|
| محرر الجداول ومحرر SQL | قاعدة بيانات البيئة نفسها، بحساب الدخول الخاص بـ Studio |
| مستخدمو المصادقة | خدمة Auth الخاصة بالبيئة |
| حاويات Storage وملفاتها | ملفات البيئة نفسها |

يرى محرر SQL كل الصفوف، ومنها الصفوف التي يخفيها أمان الصفوف، كما يفعل Studio على Supabase. لا يستطيع تغيير مخططات Auth وStorage، ولا إنشاء أدوار، ولا الوصول إلى قاعدة بيانات بيئة أخرى.

صفحات السجلات وRealtime وEdge Functions في Studio تنتظر خدمات منصة Supabase نفسها، فتبقى فارغة أو مخفية. استخدم لوحة الإدارة لها: [السجلات والمقاييس](logs-and-metrics.ar.md) و[Realtime](realtime.ar.md) و[Edge Functions](edge-functions.ar.md).

## كيف يبقى آمنًا

- يؤدي تغيير سياسة MFA أو تسجيل الخروج إلى إبطال جلسات اللوحة.
- لكل بيئة عنوان Studio خاص بها، وجلسة بيئة لا تفتح بيئة أخرى أبدًا.
- تعطي الواجهة تذكرة صالحة لدقيقة واحدة، وتتحول التذكرة إلى ملف تعريف جلسة صالح لثماني ساعات لذلك العنوان وحده. دونه لا يصل شيء إلى Studio.
- فقدان دور المالك أو المدير يغلق الوصول من الطلب التالي.
- يدخل Studio إلى قاعدة البيانات بحساب خاص به، لا يوجد إلا أثناء عمل Studio، ويأخذ كلمة مرور جديدة مع كل تشغيل. ليس مستخدمًا خارقًا ولا يملك أي شيء.
- إيقاف Studio، أو إعادة تشغيل صباربيز، يغلق ذلك الحساب ويزيل الحاويتين.

## الذاكرة

يستهلك Studio أثناء عمله حتى 768 MiB (‏Studio ‏512 MiB وpostgres-meta ‏256 MiB). إذا لم تكفِ ذاكرة الخادم يفشل التشغيل برسالة واضحة ولا يُمس أي شيء آخر. أوقف Studio عندما تنتهي.

يشغّل CI ‏Studio على جهاز نظيف مع كل تغيير، ويستخدم عبره قائمة الجداول وSQL والمستخدمين والحاويات، ويتحقق من كل حالة رفض مذكورة أعلاه، ثم يوقفه ([الدليل](../evidence/docker-studio-checks.json)).
