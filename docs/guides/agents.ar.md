# وكلاء الذكاء الاصطناعي والواجهة البرمجية

يتّصل وكيل مثل Claude Code أو Cursor أو Codex برمز وصول محدد النطاق والصلاحيات. يحتاج كلّ طلب إلى الصلاحية المناسبة وإلى دور يسمح به في المنظمة. وبحسب الصلاحيات الممنوحة، يستطيع الوكيل أن:
- ينشئ المشروع؛
- يشغّل الترحيلات؛
- ينشر دوال Edge Functions؛
- يضبط أسرارها؛
- يقرأ السجلات؛
- يكتب إعدادات التطبيق.

يتصل الوكيل برمز وصول شخصي وعنوان MCP في الخادم. يستخدم هذا العنوان خادم MCP الرسمي من Supabase.

## 1. إصدار رمز وصول

1. في لوحة الإدارة، افتح صفحة رموز الوصول. يحمل القسم الجديد عنوان **صلاحيات الوكلاء**.
2. اكتب اسمًا يوضح الوكيل الذي سيستخدم الرمز.
3. اختر مشروعًا واحدًا أو منظمة واحدة أو كل ما يسمح به دورك. الاختيار الافتراضي مشروع واحد.
4. اختر القراءة فقط أو إدارة الإعدادات أو صلاحيات محدّدة أو كلّ الصلاحيات المتاحة للوكيل. الاختيار الافتراضي هو القراءة فقط. يمكن تغيير كلّ صلاحية على حدة.
5. تحتاج الصلاحيات الخطرة إلى إقرار مستقل. تنفيذ SQL ونشر كود الدوال وإصدار مفاتيح API السرية قد يتيح تغيير البيانات أو حذفها.
6. حدد مدة الصلاحية، ثم اختر **إصدار الرمز**. يظهر الرمز مرة واحدة فقط.

لكل رمز نطاق واحد. إذا احتاج كل مشروع أو منظمة إلى صلاحيات مختلفة، يصدر له رمز مستقل. يشمل نطاق المنظمة مشاريعها الحالية والمستقبلية، ويشمل النطاق الكامل كل مورد يسمح دور صاحب الرمز بالوصول إليه الآن ولاحقًا. لا يتجاوز الرمز الدور الحالي لصاحبه.

يبدأ الرمز بـ `sbp_` ثم 40 محرفًا. يحتفظ الخادم ببصمته فقط. يستطيع رمز المشاهد عرض المعلومات التي يسمح بها دوره؛ أما SQL والمفاتيح وكود الدوال والتغييرات فتحتاج إلى دور مالك أو مشرف أيضًا.

بعد هذا التحديث في المصدر، تحصل الرموز الموجودة على صلاحيات القراءة فقط. لاستعادة الكتابة أو تغيير الصلاحيات، يُلغى الرمز القديم ويصدر رمز جديد. قد يعمل الخادم المنشور بإصدار أقدم لا يتضمن هذه التغييرات؛ يجب التحقق من النسخة المثبتة قبل الاعتماد عليها.

## 2. اربط الوكيل

العنوان هو عنوان لوحة الإدارة يتبعه `/mcp`، مثل `https://console.example.com/mcp`.

**Claude Code**: نفّذ هذا الأمر مرة واحدة في الطرفية:

```bash
claude mcp add --transport http sbarbase https://console.example.com/mcp --header "Authorization: Bearer sbp_..."
```

**Cursor** (`.cursor/mcp.json`)، و**VS Code** (`.vscode/mcp.json`، مع `"type": "http"`)، وغيرهما مما يقبل عنوانًا وترويسات:

```json
{
  "mcpServers": {
    "sbarbase": {
      "url": "https://console.example.com/mcp",
      "headers": {"Authorization": "Bearer ${env:SBARBASE_ACCESS_TOKEN}"}
    }
  }
}
```

**Codex** (`~/.codex/config.toml`):

```toml
[mcp_servers.sbarbase]
url = "https://console.example.com/mcp"
bearer_token_env_var = "SBARBASE_ACCESS_TOKEN"
```

لا تضع الرمز في ملفات تُرفع إلى المستودع. الأمثلة أعلاه تقرؤه من متغير بيئة حيث يسمح العميل بذلك.

## 3. اطلب

في مجلد أي مشروع، قل مثلًا: "انشر هذا التطبيق على Sbarbase: أنشئ مشروعًا، وطبّق الترحيلات في supabase/migrations، وانشر الدوال في supabase/functions، واكتب العنوان والمفتاح العام في .env". و[مهارة صباربيز](#مهارة-صباربيز-لـ-claude-code) تعلّم Claude Code هذه الخطوات.

## ما يستطيع الوكيل فعله

تحافظ نقطة الاتصال المستضافة على أدوات Supabase الرسمية، وتضيف أداتي الإدارة الموضحتين أدناه. يفرض الخادم الصلاحيات على كلّ طلب، حتى لو عرض العميل أداة لا يسمح الرمز باستخدامها. وتشمل الأدوات الرسمية:

| المجموعة | الأدوات |
| --- | --- |
| الحساب | `list_organizations`، `get_organization`، `list_projects`، `get_project`، `create_project` (بعد `get_cost` و`confirm_cost`، والكلفة هنا صفر دائمًا، والمنطقة التي تطلبها تُتجاهل) |
| قاعدة البيانات | `list_tables`، `list_extensions`، `list_migrations`، `apply_migration`، `execute_sql` |
| Edge Functions | `list_edge_functions`، `get_edge_function`، `deploy_edge_function` |
| التطوير | `get_project_url` (عنوان المشروع على هذا الخادم)، `get_publishable_keys` (وبصلاحية `keys.write` يمكن إنشاء مفتاح اسمه `default` إن لم يكن للمشروع مفتاح يمكن عرضه) |
| التشخيص | `get_logs` (سجلات الطلبات وAuth وStorage وRealtime وEdge Functions)، `get_advisors` (الأمان: الجداول العامة التي لم يُفعَّل فيها أمان مستوى الصفوف) |

ولا يحصل الرمز المخصص للقراءة إلا على أدوات القراءة. يعمل SQL للقراءة ما لم يمنح الرمز صلاحية `database.write` صراحة، حتى لو سمح بتعديل إعدادات أخرى. تحمي معاملة القراءة البيانات المخزنة، لكنها لا تمنع كل أثر تشغيلي، مثل الأقفال أو إلغاء جلسات قاعدة البيانات التي يسمح الحساب بإلغائها.

ما لم يتوفر بعد:
- توليد أنواع TypeScript. استعمل `supabase gen types typescript --db-url` مع [سلسلة الاتصال بقاعدة البيانات](database-access.ar.md).
- الفروع وإيقاف المشاريع مؤقتًا وحذفها. احذف المشروع من لوحة الإدارة.
- إدارة حاويات التخزين وكائناتها وإعدادات Storage الكاملة المتاحة في المنصة المستضافة. لا يتيح سجل الإدارة الحالي التحكم بالحاويات أو الكائنات.

## إدارة المشروع عبر MCP وAPI

تعرض أداة `get_sbarbase_operations` العمليات المتاحة للرمز ووصف مدخلاتها. وتقبل أداة `execute_sbarbase_operation` طلبًا مثل:

```json
{
  "operation": "auth.settings.read",
  "project_ref": "abcdefghijklmnopqrst"
}
```

قيمة `project_ref` هي مرجع البيئة المؤلف من 20 حرفًا في استجابة `GET /v1/projects`، وليست معرّف المشروع من نوع UUID. تستخدم عمليات المنظمة الحقل `organization_id`. لا يسمح رمز المشروع بتنفيذ عمليات المنظمة لعرض مشاريع أخرى أو قراءة سجل نشاط المنظمة.

وتتاح العمليتان عبر HTTP على المسارين:

- `GET /v1/agent/operations`
- `POST /v1/agent/execute` مع `{operation, project_ref?, organization_id?, input?, dry_run?}`.

تنفذ عمليات القراءة مباشرة. تبدأ عمليات الكتابة بالمعاينة افتراضيًا. تتحقّق المعاينة من العملية والنطاق والصلاحية دون استدعاء مسار التعديل. لا تفحص المعاينة كل قيمة، ولا تحجز نسخة الإعدادات، ولا تحاكي SQL أو تنشئ نسخة احتياطية، ولا تضمن نجاح التنفيذ اللاحق. يحتاج التنفيذ إلى `dry_run: false`، ويعيد الخادم عنده فحص الصلاحيات والمدخلات عبر مسار الإدارة المعتاد.

لتعديل روابط إعادة التوجيه، يقرأ الوكيل `auth.settings.read` أولًا، ثم يحافظ على الإعدادات المطلوبة ويرسل التعديل المقصود في `input` إلى `auth.settings.update`. يضاف `base_revision` من الاستجابة السابقة لرفض تعديل بني على نسخة قديمة. بعد المعاينة، ينفذ الطلب مع `dry_run: false`، ثم يقرأ الوكيل الإعدادات وحالة تطبيقها من جديد. تشمل الحقول المدعومة `site_url` و`redirect_urls` وإعدادات التسجيل والموفرين والجلسات. يبقى التحقق من المدخلات وتطبيق الإعدادات بالطريقة المعتادة في لوحة الإدارة.

تصف قائمة العمليات أيضًا ما يدعمه الخادم من إعدادات SMTP وSMS وقوالب البريد وSSO وأسماء المشاريع والبيئات وواجهة البيانات والمهام المجدولة وRealtime والدوال وأسرارها والمفاتيح والسجلات والمقاييس. يرفض الخادم العمليات المجهولة وعناوين الإدارة غير المدرجة. يعتمد الوكيل على القائمة الحالية عند اختيار اسم العملية.

### قائمة الصلاحيات

| الصلاحية | ما تسمح به |
| --- | --- |
| `projects.read` | عرض المشاريع والبيئات |
| `projects.write` | إنشاء المشاريع والبيئات وتعديل أسمائها |
| `organization.read` | عرض المنظمة ومعلومات الأعضاء المسموحة |
| `organization.write` | تعديل اسم المنظمة |
| `auth.read` | عرض إعدادات Auth المدعومة مع إخفاء الأسرار |
| `auth.write` | تعديل أمان تسجيل الدخول وروابط إعادة التوجيه والموفرين والبريد الخاص بالمشروع |
| `auth.delete` | حذف موفر SSO، بصلاحية خطرة مستقلة |
| `database.read` | قراءة حالة الاتصال وواجهة البيانات وتقارير فحص أمان قاعدة البيانات وتشغيل SQL للقراءة عندما يسمح دور صاحب الرمز |
| `database.configure` | تعديل إعدادات واجهة البيانات والمهام المجدولة المدعومة |
| `database.write` | تنفيذ SQL والترحيلات وتمكين الاتصال المباشر بقاعدة البيانات، بصلاحية خطرة مستقلة |
| `functions.read` | عرض الدوال وقراءة كودها وأسماء أسرارها عندما يسمح الدور |
| `functions.write` | نشر كود الدوال وإعداد خدمتها وأسرارها، بصلاحية خطرة مستقلة |
| `functions.delete` | حذف الدوال، بصلاحية خطرة مستقلة |
| `storage.read` | قراءة معلومات التخزين التي تدعمها الواجهة المثبتة |
| `keys.read` | عرض المفاتيح العامة وبيانات المفاتيح غير السرية |
| `keys.write` | إصدار مفاتيح API، بما فيها المفاتيح السرية، بصلاحية خطرة مستقلة |
| `keys.delete` | إلغاء مفاتيح API، بصلاحية خطرة مستقلة |
| `logs.read` | عرض السجلات والمقاييس وأحداث التدقيق المسموحة |
| `realtime.read` و`realtime.write` | عرض إعدادات Realtime المدعومة وتعديلها |

تستبعد مجموعة إدارة الإعدادات تنفيذ SQL ونشر الكود وإصدار المفاتيح السرية وصلاحيات الحذف والإلغاء. وقد تؤثر تغييرات Auth أو واجهة البيانات في أمان التطبيق أو توافره؛ هذه المجموعة لا تضمن صحة قرارات الوكيل. أما SQL والكود والمفاتيح السرية فقد تسمح بآثار مدمّرة للبيانات. تمنح هذه الصلاحيات عند الحاجة فقط، ويفضل تجربتها في بيئة منفصلة أولًا.

الربط هنا يدوي برمز وصول. لا يضيف هذا التحديث تسجيل الدخول عبر OAuth أو تسجيل موصل مستضاف في ChatGPT أو claude.ai.

## كيف يبقى ذلك آمنًا

- **SQL.** يعمل بحساب المطوّر الخاص بالبيئة، وهو حساب [الاتصال بقاعدة البيانات](database-access.ar.md) نفسه: وصول كامل إلى قاعدة تلك البيئة وحدها، دون صلاحيات المدير العام، ودون الوصول إلى بيئة أخرى. ويستطيع إنشاء مخططات خاصة به، لكن ليس باسم تستخدمه المنصة ([الاتصال بقاعدة البيانات](database-access.ar.md)). وإن كان الوصول إلى قاعدة البيانات مغلقًا، فقد يفعّله أول طلب SQL لتغيير البيانات، ثمّ يطلب الخادم المحاولة بعد دقيقة. أما طلب القراءة فلا يفعّله أبدًا. وللبيئة التي كان الوصول فيها مفعّلًا قبل 0.5.0، أوقفه ثم شغّله مرة واحدة من لوحة الإدارة، لتحصل على مخطط سجل الترحيلات.
- **رموز القراءة فقط.** يعمل SQL هنا للقراءة فقط على الخادم نفسه، أيًّا كان ما يطلبه الوكيل. يُنفَّذ عبارةً واحدة داخل معاملة للقراءة فقط تُلغى دائمًا، فلا يتغير أي شيء من البيانات، ولا تستطيع `COMMIT; ...` الخروج منها ([الدليل](../evidence/agent-sql-checks-2026-10-17.json)). لكنه ما زال يعمل بحساب المطوّر، فتستطيع العبارة الواحدة ما يستطيعه ذلك الحساب خارج البيانات: إلغاء جلسات قاعدة بيانات هذه البيئة نفسها، أو حجز قفل حتى المهلة البالغة 130 ثانية. ويستطيع تشغيلَ SQL رمزُ القراءة الخاص بالمالكين والمشرفين، لا المشاهدين.
- **التغييرات.** يمر كل تغيير عبر مسارات لوحة الإدارة نفسها، بفحوص الأدوار نفسها وسجل التدقيق نفسه، ويظهر فيه باسمك.
- **انتهاء الرمز.** تتوقف الطلبات الجديدة فورًا حين تلغيه، أو حين تنتهي صلاحيته، أو حين يُعاد تعيين كلمة مرورك من الخادم ([إعداد المشغّل](operator-setup.ar.md#نسيت-كلمة-المرور))، أو حين تتغير سياسة المصادقة الثنائية في التثبيت. أما الاستعلام الذي بدأ فيكمل أو يبلغ مهلته. ولا ينتهي الرمز حين تسجّل الخروج من لوحة التحكم، ولا حين تنتهي جلستك فيها فتُخرجك تلقائيًا. قبل الإصدار 0.5.13 كان كلاهما ينهيه، فإن توقف رمز أنشأته من قبل فأنشئ رمزًا جديدًا مكانه. وإن أُزيلت عضوية أو خُفّض دور، طُبّق ذلك من الطلب التالي.
- **التدقيق.** يُسجَّل في سجل النشاط كل ترحيل وكل SQL قد يغيّر البيانات، مع معرّف الرمز وبصمة للاستعلام، دون الاستعلام نفسه.
- **ما لا يستطيعه الرمز.** لا يصدر رموز وصول ولا يعرضها ولا يلغيها، ولا يغير أمان الحساب الإداري أو سياسة التثبيت، ولا يحذف المشاريع والبيئات نهائيًا. تختلف إعدادات Auth الخاصة بالمشروع عن أمان الحساب الإداري؛ يمكن تعديل الإعدادات المدعومة للمشروع بصلاحية `auth.write`.
- **حد الطلبات.** لكل رمز 300 طلب في الدقيقة.

ما يكتبه الوكيل ليس مراجعة. راجع ما غيّره قبل أن تعتمد عليه، كما تفعل مع أي تغيير آلي. وأعطِ كل وكيل رمزه الخاص، لتستطيع إلغاء واحد وحده.

## الواجهة المتوافقة مع Supabase

يعمل الرمز نفسه مع أجزاء واجهة الإدارة في Supabase التي تستعملها الأدوات، على `https://console.example.com/v1/...`:

```bash
curl -H "Authorization: Bearer $SBARBASE_ACCESS_TOKEN" https://console.example.com/v1/projects
```

| واجهة Supabase | على صباربيز |
| --- | --- |
| `GET /v1/organizations`، `/v1/organizations/{slug}` | منظماتك |
| `GET /v1/projects`، `/v1/projects/{ref}`، `POST /v1/projects` | كل بيئة "مشروع" بلغة Supabase: `ref` من 20 حرفًا، و`api_url` عنوانها هنا. و`POST` ينشئ مشروعًا مع بيئة الإنتاج الخاصة به |
| `GET` و`POST /v1/projects/{ref}/api-keys`، و`DELETE .../api-keys/{id}` | [مفاتيح API](api-keys.ar.md). قيمة `api_key` للمفتاح العام تُقرأ دائمًا، أما المفتاح السري فلا يظهر إلا عند إنشائه |
| `POST /v1/projects/{ref}/database/query` | SQL: `{query, parameters?, read_only?}` |
| `GET` و`POST /v1/projects/{ref}/database/migrations` | سجل الترحيلات في `supabase_migrations.schema_migrations`، كما يحفظه Supabase CLI |
| `GET /v1/projects/{ref}/functions`، `.../functions/{slug}`، `.../functions/{slug}/body`، `POST .../functions/deploy?slug=`، `DELETE .../functions/{slug}` | [Edge Functions](edge-functions.ar.md) |
| `GET` و`POST` و`DELETE /v1/projects/{ref}/secrets` | أسرار الدوال، تُعرض بأسمائها فقط |
| `GET /v1/projects/{ref}/analytics/endpoints/logs`، `/advisors/security`، `/advisors/performance` | السجلات والتنبيهات |
| `GET`، `PATCH /v1/projects/{ref}/postgrest` | المخططات المكشوفة ومسار البحث الإضافي وحد الصفوف ([واجهة البيانات](data-api.ar.md)) |

وأي طلب آخر يُجاب بـ `404` أو `501` مع رسالة توضّح السبب.

### خادم MCP الرسمي من Supabase على جهازك

يمكن أيضًا تشغيل خادم MCP من Supabase على جهازك وتوجيهه إلى هذا الخادم:

```bash
bunx @supabase/mcp-server-supabase@latest --api-url https://console.example.com --access-token sbp_...
```

يعمل، مع فروق: أداته `get_project_url` تذكر نطاقًا من نطاقات `supabase` بدل هذا الخادم، ويعرض أداة لاستعلامات سجلات ClickHouse وتنبيهات صحة لا يجيب عنها هذا الخادم. أما النقطة المستضافة أعلاه فتعطي العنوان الصحيح والأدوات التي تعمل فقط، فهي الأفضل.

### Supabase CLI

يتصل Supabase CLI بهذا الخادم عبر ملف إعداد (profile):

```yaml
name: sbarbase
api_url: https://console.example.com
dashboard_url: https://console.example.com
project_host: console.example.com
```

```bash
export SUPABASE_ACCESS_TOKEN=sbp_...
supabase --profile ./sbarbase-profile.yaml projects list
supabase --profile ./sbarbase-profile.yaml functions deploy hello --project-ref <ref> --use-api
supabase --profile ./sbarbase-profile.yaml secrets set STRIPE_KEY=... --project-ref <ref>
```

جُرّبت هذه الأوامر الثلاثة على خادم حقيقي. يحتاج `functions deploy` إلى `--use-api`، فبدونه يجمّع CLI الدالة بـ Docker ويرفعها بصيغة لا يقرؤها هذا الخادم. أما الأوامر التي تتصل بقاعدة البيانات عبر اسم مضيف المشروع، مثل `db push --linked`، فلا تعمل؛ وللترحيلات راجع [الوصول إلى قاعدة البيانات](database-access.ar.md).

## مهارة صباربيز لـ Claude Code

في المستودع مهارة تشرح لـ Claude Code ما يعنيه "انشر على Sbarbase": ترتيب الخطوات، وأين يكتب العنوان والمفتاح، وما يتحقق منه بعد ذلك. انسخها مرة واحدة:

```bash
mkdir -p ~/.claude/skills/sbarbase && curl -fsSL https://raw.githubusercontent.com/M7MMAD-OMAR/sbarbase/main/deploy/agent-skill/sbarbase/SKILL.md -o ~/.claude/skills/sbarbase/SKILL.md
```

## الحدود

- الموصلات المستضافة في claude.ai وChatGPT تحتاج OAuth، ولا يقدّمه صباربيز بعد. استعمل عملاء يقبلون ترويسة: Claude Code وCursor وVS Code وCodex وGemini CLI، وواجهتي Claude وOpenAI البرمجيتين.
- يعمل طلب SQL الواحد 120 ثانية على الأكثر، ويعيد 5 MiB على الأكثر.
- تُسجَّل تغييرات الوكيل عبر مسارات لوحة الإدارة باسمك أنت، أما SQL والترحيلات فتحمل معرّف الرمز أيضًا.
- الترحيل الذي يطبّقه وكيل يأخذ وقت تطبيقه رقمًا لإصداره، كما في Supabase، لا الوقت المكتوب في اسم ملفه في المستودع. ولذلك لا يطابق السجل أسماء الملفات في المستودع، بل يسجّل ما طُبّق ومتى.


## التحقق من الميزات قبل تعديل المشروع

يوفّر المصدر العامّ 0.12.2 المسار `GET /v1/capabilities` برمز وصول شخصيّ، أو مورد MCP باسم `sbarbase://capabilities` عبر `resources/list` ثمّ `resources/read`. يعيد كلاهما سياسة التثبيت نفسها مع رقم إصدارها، ولا يفحصان الإضافات المثبّتة أو صحّة الخدمات أو صلاحيات الرمز. يُتحقق من التفويض لكلّ عمليّة لاحقة.

لم تدخل هذه الإضافات ولا حزم SDK الأحدث في تعديل لوحة المالك الخاصّ المبنيّ على 0.11.2. وقد يعيد تثبيت أقدم استجابة 404 أو يعلن أنّ مورد MCP غير معروف. تحقق من [النسخة المثبّتة](../reference/status.ar.md)، واستخدم أوامر المشاريع والواجهات المتوفّرة فيها. غياب مسار الاكتشاف لا يعني غياب جميع عمليات API.

البيئات قواعد مستقلّة، وليست فروع Git. لا تتوفّر فواتير Supabase المستضافة أو استعلامات ClickHouse الحرّة أو GraphQL أو جميع مستشاري المنصة السحابيّة. ولا يجوز للوكلاء محاولة تجاوز حظر `pg_stat_statements` أو منح أدوار الخادم المشترك للوصول إلى إحصاءات بيئات أخرى.

يصف المصدر العامّ محوّل PGMQ يتطلّب ترحيلًا يدويًّا معلنًا. لا تفعّل الإضافة اعتمادًا على اسمها في قائمة Studio أو بيانات الاكتشاف وحدها. يلزم أوّلًا أن يتحقق المشغّل من صلاحيّة مسار الترحيل والنسخ الاحتياطيّ والاستعادة، ثمّ يفحص `pg_extension` في البيئة المقصودة. لا يلغي التراجع عن كود التطبيق تغييرات ملكيّة البيانات. راجع [الترقيات](upgrades.ar.md) و[Studio](studio.ar.md).

يعتمد دعم SMTP الأصليّ على نسخة المصدر وصورة Studio المثبّتة؛ راجع [Studio](studio.ar.md#إعدادات-البريد-في-studio). لا يشمل الإصدار العامّ v0.12.2 هذا الإصلاح. يقبل المحوّل حقول SMTP فقط، ولا يتيح تعديل إعدادات المصادقة الأخرى الخاصّة بالمنصّة المستضافة. يستطيع الوكلاء الاستمرار في استخدام واجهة إعدادات Sbarbase المدعومة، مع التحقّق من حالة تطبيق الإعدادات ومن قبول طلب إرسال بريد فعليّ، كلٍّ على حدة.
