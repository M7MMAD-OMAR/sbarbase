# إصدار اعتمادات تخزين Fanio

يضيف هذا الإصدار خدمة تمنح بيانات اعتماد للتخزين فقط، ضمن بيئة Fanio الحالية. لا تنشئ الخدمة حاويات تخزين أو أدوار قاعدة بيانات، ولا تنقل الملفات أو تغيّر صور الخدمات. يستمر Fanio في استخدام R2 حتى تجتاز عملية النقل فحوصها المستقلة.

تقرأ الخدمة سياسة من الملف `.secrets/upstream/storage-runtime-credentials.json`. يملك ملف السياسة حساب الخدمة، وتكون صلاحياته `0600` ونسخته `1`. تُحفظ السياسة باستبدال الملف دفعة واحدة. تحتوي سجلاتها على بصمات SHA256 لقيم الاعتماد الأولية، وتربط كل قيمة بالبيئة والغرض ورقم جيل الاعتماد والدور. تُرفض إعادة استخدام البصمة لغرض آخر أو في بيئة أخرى. تُحفظ القيم الأصلية في أسرار خادم Fanio، وتبقى مفاتيح توقيع البيئات على Sbarbase. ويلزم مفتاح بوابة قابل للنشر منفصل عنها.

للملفات الأصلية ولملفات الإثبات قيم اعتماد أولية وأدوار مستقلة. تُصدر الخدمة رموز JWT بقيمة audience تساوي `sbarbase:storage`، وتنتهي صلاحيتها بعد 3600 ثانية. حذف سجل من السياسة يمنع إصدار رموز جديدة، لكنه لا يلغي رمزًا سبق إصداره. يتطلب الإلغاء الفوري تغيير صلاحيات الدور المعني أو هوية توقيع البيئة.

ترفض بوابة HTTP رموز audience الخاصة بالتخزين على المسارات الأخرى. لا يشمل هذا الفحص الرموز داخل رسائل Realtime عبر WebSocket. ولا يشمل نطاق التحقق الحالي Realtime أو الوظائف.

تغطي الاختبارات المحلية خدمة الإصدار وقراءة الملفات الخاصة والبوابة، وإعدادات Fanio ورموزه واتصال خدمة الإصدار بعميله. لا تكفي هذه الاختبارات وحدها لاعتماد الخادم المثبت. تحتاج خصائص الأدوار المثبتة وسياسات الوصول وخصوصية حاويات التخزين وقبول التوقيع الأصلي وصلاحيات API إلى أدلة تشغيل مستقلة.

طبّق الإصدار الآمن الموقّع المحدد عبر طلب التحديث المعتمد في واجهة الإدارة. يفرغ المشرف الأعمال الجارية، ثم يطبّق الإصدار مع الحفاظ على إدارة الخدمات الخلفية. يتطلب تسليم التحكم شروطه الحالية، ولا يضمن بقاء وحدة التحكم متاحة دون انقطاع. لا تقتل عملية Bun أو ترسل إليها إشارات يدويًا، ولا تستخدم `systemctl restart` أو تستبدل مسار التفعيل المنسق بأمر `upgrade.py start --to` مباشر.

استخدم طلب التراجع المعتمد في واجهة الإدارة بعد اجتياز شروطه. احفظ البيانات، والإعدادات التي تحدد مواقع قراءة البيانات الحالية، وسجلات الاستعادة المستقلة. وأبقِ كتابة البيانات محصورة في نظام التخزين الأصلي. لا يعني التراجع عن خدمة الإصدار استعادة بيانات تجارية قديمة أو حذف حاويات التخزين أو ملفاتها.

يحذف وكيل TLS قيمة Host العامة قبل إرسال الطلب إلى مستمع وحدة التحكم المحلي. تقبل خدمة الإصدار هذا المسار عندما يثبت المضيف أن الطلب وصل عبر المستمع المحلي الثابت المضبوط، وتتطابق ترويسة Host معه، ويضيف الوكيل اسم المضيف العام المضبوط ومخطط HTTPS. لا تكفي ترويسات التمرير وحدها. تبقى المنافذ الأخرى والطلبات التي تحمل ترويسة `Origin` أو `Sec-Fetch-Site` وسلاسل الاستعلام وأجسام الطلبات مرفوضة. يغطي اختبار اتصال محلي فعلي هذا المسار.

تُحدد وجهة الوكيل من محلل `SBARBASE_CONSOLE_PORT` نفسه المستخدم في البوابة، وتبقى ثابتة عند تفعيل النسخة المرشحة. المستمع الخاص المؤقت لفحص المرشح وMCP ليس وجهة معتمدة لوكيل TLS. يفحص اختبار منفصل هذا الفصل، واختبار آخر معزول يستخدم وكيل TLS وعميل رموز Fanio الفعليين مع شهادة موثوقة خاصة بالاختبار. يتحقق الاختبار من نجاح الإصدار ورفض المتصفح والمضيف الخاطئ والشهادة غير الموثوقة. ولا يثبت نجاح الإجراء على خادم مثبت.

يُحفظ إثبات مصدر الاتصال في WeakMap داخل العملية، ويرتبط بكائن Request الأصلي الذي ينشئه `serveLocal`. يسجل الإثبات المستمع المحلي الفعلي، أو اتصالًا داخليًا ثبت أن المستمع الأمامي المقابل هو الذي فتحه. لا تستطيع ترويسات Host والتمرير إنشاء هذا الإثبات. تقارنه خدمة الإصدار بمنفذ وحدة التحكم الثابت المضبوط، وترفض منفذ المرشح الخاص والوصول المباشر إلى الاتصال الداخلي، حتى مع ترويسة Host مزورة. لا تتغير سياسة التوجيه أو ملكية المستمعين.
